# ScholarShelf — School Run Sheet (one page)

**For:** the person coordinating book distribution at your school. Print this. Follow it top to bottom. Do the steps **in order** — the order is what keeps it from breaking on the day.

**Golden rule:** never open parent invites until finance has locked the allocations. If you invite parents first, they log in to pay for nothing and you get a flood of confused messages.

**Plain-language glossary (so nobody hunts for the wrong button):**
- **Book** = a title in your catalogue. **Bundle** = the set of books for a class/year. **Allocation** = finance saying "this class gets this bundle." **Basket** = the order that appears for a parent *automatically* after a teacher confirms their child received the books. You don't create baskets — the system does.

## The sequence (who does what, when)

| # | Step | Who | When | Done ✅ |
|---|------|-----|------|--------|
| 1 | **Set up the school** (branding, payment app name) | Admin | Summer, before term | |
| 2 | **Build the catalogue + bundles** (add books, group into bundles per class). Keep it — it's ~80% reusable next year | Admin | Summer | |
| 3 | **Register the physical books** — generate copies, print barcode labels, apply, scan-to-confirm. **Book a room + 3–4 helpers; do it in 1–2 sessions.** Test the printer + scanner on 10 books first | Admin + volunteers | 2–3 weeks before term | |
| 4 | **Assign bundles to classes**, then **finance locks the allocations** | Admin → Finance | After step 3 | |
| 5 | **Add students + parents by CSV import** (not one-by-one invites), then open parent onboarding | Admin | 2–3 weeks before distribution | |
| 6 | **Parents pay** and submit their payment reference (or "Pay for all children"). Set a **hard deadline ≥5 days before collection** — finance confirms each payment by hand | Parents → Finance | Rolling | |
| 7 | **Teacher confirms "received"** for each child **the day stock physically arrives** — not on handout morning | Teacher | On stock arrival | |
| 8 | **Collection day.** Hand over books against the printed paid-roster (see below) | Teacher/volunteers | Distribution day | |

## Pick your track (by school size)

**Large / well-staffed school** — keep the roles separate: Admin sets up, Finance handles allocations + payment confirmation, Teachers confirm distribution. Full per-copy barcode registration is worth it.

**Small / volunteer / weekend school** — **compress the roles.** One or two people play admin + finance (the staff invite wizard supports one person holding multiple roles). Keep intake light: batch the barcode scanning into a single session, or skip per-copy scanning entirely and just track stock by quantity. **Don't half-do the labelling** — a partly-scanned batch is worse than none.

---

## Collection day — the offline fallback (do this every time)

The app does **not** yet auto-match a paid payment to a physical book. So the night before:

1. Print a **paid roster per class** (who has paid, what they ordered).
2. Hand books out against the paper list. Tick as you go.
3. If the wifi or app fails, the paper roster keeps the queue moving.

---

## When something goes wrong (name ONE person for this)

Appoint a single **Reconciliation Owner** (finance or admin). Every exception goes to them, logged:

- **Paid but out of stock** → backorder or offer a substitute; note it against the child.
- **Damaged book** → replace from spare stock; mark the copy `damaged`.
- **Payment reference wrong / disputed** → confirm against the payment app, then approve or reject in ScholarShelf.
- **Refund** → agreed and paid outside the app (bank/cash); record it in the notes.

Don't let these get solved ad-hoc by whoever's nearest — one owner, one log.

---

## Key deadlines to set and announce

- Parent payment deadline: **≥5 days before collection.**
- Book registration finished: **before parent invites go out.**
- Teacher "received" confirmations: **on stock arrival, not handout day.**

---

## Year rollover (books are sold fresh each year)

At the start of a new year, start a **new academic-year batch** of copies rather than reusing last year's records, so old links don't cause phantom "already collected" errors. Keep the catalogue and bundles — just regenerate the copies.
